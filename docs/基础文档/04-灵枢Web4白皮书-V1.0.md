摘要
灵枢 Web4 是一个完全私有化、全平台、由 AI Agent 驱动的去中心化智能中枢。它赋予每个用户一个可自托管的 AI 助理，同时作为 DID 身份钱包、语义数据保险箱 和 链上工作流引擎，实现人与 Web4 的自然交互。

本文档阐述了灵枢 Web4 的系统架构、去中心化协议、代币经济模型（LSP）、治理机制以及未来路线图。

1. 引言
1.1 Web 4.0 的愿景
Web 1.0 是只读的信息网，Web 2.0 是读写交互的社交网，Web 3.0 是价值转移的资产网。而 Web 4.0 是人机共生的智能网——AI 不再是外挂的工具，而是内嵌于协议层的原生能力；用户不再只是“使用”AI，而是与 AI 组成混合智能体，共同管理身份、数据、资产和工作流。

灵枢 Web4 的使命是：让每一个个体都能拥有一个不受平台限制、数据自主、可与任何 Web4 应用互操作的 AI 代理。

1.2 当前 AI 助理的困境
现有 AI 助理（如 ChatGPT、Claude、Copilot）存在四个根本性问题：

问题	描述
中心化垄断	AI 推理服务、用户数据、模型参数全部由单一公司控制，用户无任何议价权
数据主权丧失	对话记录、上传文件被用于训练模型，用户无法删除或迁移
身份割裂	每个 AI 平台都需要独立注册，无法跨应用使用同一身份
无法执行链上操作	AI 只能“建议”而不能“行动”，无法完成转账、签名、调用合约等真实世界任务
灵枢 Web4 通过去中心化身份（DID）、本地推理 + 链上验证、语义工作流引擎和代币经济，系统性地解决了上述问题。

1.3 灵枢的独特路径：AI Agent 替代真人，降低成本并再投资
传统软件公司开发灵枢同等规模的产品（全平台 C++ 核心 + AI 语音 + 视觉 + 小云端 + Web4 功能）需要 100 人以上的真人团队，年度人力成本超过 4000 万人民币。

这种模式使得灵枢的研发人力成本降低到传统模式的 1/5。我们将节约下来的资金全部以透明的方式再投资于：

2.2 核心引擎（已有）
纯 C++ 全平台：Windows/macOS/Linux/iOS/Android/Web 统一代码库

真人级 AI 语音通话：端到端延迟 <300ms，支持打断、自然轮替、音色克隆

私有化部署：所有 AI 模型在用户本地（或自托管服务器）运行，数据不上传

2.3 去中心化身份层（DID）
支持 did:key、did:ethr 标准

私钥本地生成并存储于 libsodium 密封盒，永不离开用户设备

助记词（BIP39）备份与社交恢复

DID Document 可选上链（以太坊）或存储在 IPFS

2.4 去中心化存储层
IPFS：内容寻址存储，所有用户数据（对话、文件、偏好）加密后上传

Filecoin：持久化存储层，用户支付 FIL 或 LSP 获得长期备份

本地缓存：常用数据保留在本地，减少网络延迟

2.5 区块链代理层
本地签名交易，私钥不接触网络

多链支持：Ethereum、Solana、Polygon、BSC

语音意图解析：将用户自然语言直接转换为交易对象（链、金额、接收方）

双重确认：语音或硬件按钮二次确认后广播

2.6 语义工作流引擎
工作流定义语言（WDL）：JSON 格式，描述触发器、动作、条件、循环

LLM 驱动：用户输入自然语言，灵枢调用本地 LLM（deepseek-r1 14B）拆解为 WDL

执行器：C++ 虚拟机，支持 HTTP 调用、合约调用、本地命令、邮件/Telegram 通知

3. 核心协议
3.1 DID 认证与密钥管理
每个灵枢 Web4 用户在首次启动时生成一个 DID 密钥对。私钥使用以下方式保护：

Windows：DPAPI + 用户登录密码派生密钥

macOS/iOS：Keychain（kSecAttrAccessibleWhenUnlocked）

Android：Android Keystore（TEE）

Linux：libsecret 或用户提供的 passphrase

DID Document 包含：

json
{
  "@context": "https://www.w3.org/ns/did/v1",
  "id": "did:key:z6Mkr...",
  "verificationMethod": [...],
  "service": [
    {
      "id": "#lingshu-storage",
      "type": "StorageService",
      "serviceEndpoint": "ipfs://Qm..."
    }
  ]
}
3.2 加密数据存储规范
上传到 IPFS 的每个文件遵循以下结构：

javascript
{
  "version": 1,
  "type": "lingshu/memory",
  "encryptedData": "base64...",
  "recipients": [
    { "did": "did:key:...", "encryptedKey": "base64..." }
  ],
  "metadata": {
    "timestamp": 1714089600,
    "conversationId": "uuid",
    "contentType": "text/plain"
  }
}
数据用对称密钥（AES-256-GCM）加密

对称密钥用每个授权接收者的公钥（X25519）加密后存储

只有持有对应私钥的用户才能解密

3.3 代理签名与交易策略
灵枢作为用户的“链上代理”，可以预先设定签名策略（例如）：

每次确认：任何交易都需要用户语音或按钮确认

白名单模式：允许向预设地址自动转账（限额内）

时间锁：大额交易延迟 24 小时执行，可在此期间取消

策略以加密形式存储在本地，签名时由灵枢核心读取并执行。

6. 安全与隐私
6.1 端到端加密
所有用户数据在离开设备前用 XChaCha20-Poly1305 加密

加密密钥由用户 DID 私钥派生，或使用独立的对称密钥（由接收方公钥加密）

即使在 IPFS 公共网关上，文件也完全不可读

6.2 本地推理与数据最小化
灵枢的 AI 模型（VAD/ASR/LLM/TTS）全部在用户本地运行（CPU/GPU/NPU）

只有用户明确授权的语义工作流才会上传到公共节点执行

灵枢官方不收集任何用户对话数据

6.3 社交恢复与多签
用户可预先指定 3-5 个监护人 DID

丢失私钥后，监护人通过社交恢复合约（ERC-4337 智能账户）发起恢复请求

恢复需要超过半数的监护人签名

6.4 安全审计
灵枢核心引擎每发布一个主版本，都会委托 Trail of Bits 或 Least Authority 进行第三方审计

智能合约（LSP 代币、质押合约、技能市场）在上线前必须通过两次独立审计

全部审计报告公开在 GitHub
