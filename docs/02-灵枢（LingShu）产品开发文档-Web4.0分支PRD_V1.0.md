## 2. Web 4.0 时代背景

### 2.1 互联网演进脉络

| 发展阶段 | 时间 | 核心特征 | 用户角色 | 关键变化 |
|---|---|---|---|---|
| Web 1.0 | 1990s-2000s | 只读 | 读者 | 信息上网，解决“阅读权” |
| Web 2.0 | 2000s-2010s | 读+写 | 参与者 | 人人上网，解决“表达权” |
| Web 3.0 | 2010s-至今 | 读+写+拥有 | 所有者 | 资产上链，解决“拥有权” |
| Web 4.0 | 未来进行时 | 读+写+拥有+执行 | 委托者 | 智能上链，万物入网，AI获得“行动权” |

### 2.2 Web 4.0 核心定义

Web 4.0 是互联网发展的下一个重大阶段，核心指向一个共同的未来：

**互联网正在从一个为人类设计的信息工具，演变为一个人类与 AI 智能体共生、共同参与的智能基础设施。**

核心理念：

- 过去：我们“自己上网”
- 未来：我们可以“委托 AI 替我们上网”

### 2.3 Web 4.0 三大视角

| 视角 | 定义 | 核心关注点 | 代表机构/人物 |
|---|---|---|---|
| 虚实融合 | 物理世界与虚拟世界的深度融合 | AR/VR、数字孪生、物联网 | 欧盟委员会 |
| AI原生 | AI智能体成为互联网的“原生居民” | 自主决策、经济行为 | 学术界 |
| 经济自主 | AI智能体作为独立经济主体 | 自主赚取、交易、拥有 | Sigil Wen 宣言 |

**灵枢定位：综合三大视角，聚焦 AI 原生 + 经济自主，逐步扩展虚实融合。**

## 6. 技术补充方案

### 6.1 A2A 通信协议（Layer 5）

```yaml
协议名称: LAP (Lingxu Agent Protocol)
版本: v0.1 (规划中)

核心组件:
  Agent Discovery:
    - 链上Agent注册表
    - 能力标签索引
    - 类似DNS的解析服务

  Message Standard:
    - 基于JSON Schema
    - 支持同步/异步消息
    - 消息签名与验证

  Collaboration Protocol:
    - 任务发布与订阅
    - 工作流编排（YAML定义）
    - 结果聚合与验证

  互操作适配器:
    - NEAR AITP网关
    - Bittensor子网接口
    - HTTP/WebSocket桥接
```

### 6.2 Agent DID 与信任体系（Layer 4）

```yaml
方案名称: AID (Agent IDentifier)
架构: 基于W3C DID标准

DID文档结构:
  id: "did:lingxu:agent:xxx"
  controller: "用户DID 或 DAO"
  publicKey: [...]
  authentication: [...]
  service:
    - type: "AgentEndpoint"
      endpoint: "https://..."
  capability:
    - skill: "code-review"
      verified: true
      proof: "链上验证引用"
  reputation:
    - score: 95
      totalVotes: 1000
      lastUpdate: "2026-..."

信任机制:
  - 能力证明: 与PoI共享验证机制
  - 信誉聚合: 跨平台信誉评分
  - 信任传播: 类似PGP信任网
```

### 6.3 数据主权层（Layer 3）

```yaml
方案名称: DSO (Data Sovereignty)

授权机制:
  - 数据粒度: 会话/消息/文件/记忆
  - 授权对象: 特定Agent/Agent类型/所有人
  - 授权期限: 单次/限时/永久
  - 撤销机制: 即时生效

审计机制:
  - 链上记录: 数据访问日志
  - 隐私保护: 零知识证明
  - 用户查询: 可视化审计报告

隐私计算（预留）:
  - TEE可信执行环境
  - 联邦学习接口
  - 差分隐私
```

## 11. 本章小结

灵枢生态是对 Web 4.0 的完整实践，通过六层架构（智能体执行层 → 经济激励层 → 数据主权层 → 信任身份层 → A2A协议层 → 多模态交互层），实现“让 AI 智能体成为互联网的自主参与者”的愿景。

核心结论：

- Web 4.0 是确定性趋势，灵枢定位与之一致
- 六层架构覆盖 Web 4.0 核心能力
- 差异化聚焦“AI训练链”而非“AI服务市场”
- 需补充 A2A 协议、Agent DID、数据主权三个模块
- 与 Bittensor / NEAR 可互操作，形成生态互补
