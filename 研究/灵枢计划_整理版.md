## 2. 核心原则：极致性能·完全自研

### 2.1 技术立场声明

灵枢项目采用**完全自研、从底层到应用**的技术路线，不依赖任何现成的操作系统、芯片平台或开发框架：

| 层级 | 方案 | 说明 |
|------|------|------|
| 芯片 | 自研 Al Body | 分布式集群 CPU Chiplet 架构，UCIe 互联，TMX/PMX 指令 |
| 操作系统 | 自研灵枢 OS | C 语言，零依赖，不基于 Linux |
| 编译器 | 各平台独立选型 | Windows: MinGW-w64/Clang，macOS: Clang，Linux: GCC |
| 客户端 | 各平台最亲密语言原生实现 | Windows: C/Win64，macOS: Objective-C/Cocoa，Linux: C/X11，Android: 纯 Java |
| 第三方依赖 | 零 | 不使用 Qt、STL（内核层）、Boost 等任何框架或库 |

### 2.2 为什么不用现有方案？

| 方案 | 拒绝理由 |
|------|----------|
| Linux 内核 | GPL 许可证传染风险，无法完全掌控，不是极致自研 |
| Qt 框架 | 依赖链复杂（5-10 层），开发体验差，体积臃肿 |
| STL（内核/系统服务层） | 通用性妥协，内存分配不可控，异常处理有开销 |
| 树莓派 / 瑞芯微 / 全志 | 非自研芯片，无法实现硬件级任务迁移和分布式算力共享 |
| MSVC 编译器 | 臃肿（几 GB），依赖 Visual Studio 生态，不符合轻量自研原则 |
| Linux 发行版 GUI（GTK/Qt） | 依赖链复杂，无法跨平台统一 |

### 2.3 各平台客户端「练兵」逻辑

每开发一个平台的原生客户端，都是一次对底层操作系统的深度解剖，经验直接回流到自研灵枢 OS：

| 平台 | 学到的核心知识 | 回流到灵枢 OS |
|------|---------------|---------------|
| Windows（C/Win64） | 消息循环、窗口管理、GDI 绘图、进程/线程模型 | GUI 服务设计、进程间通信 |
| macOS（Objective-C/Cocoa） | RunLoop、响应链、Core Graphics、Metal 图形栈设计、事件处理 | 图形栈设计、事件处理 |
| Linux（C/X11） | X11 协议、事件分发、客户端/服务器模型 | 网络透明性设计、远程桌面 |
| Android（纯 Java） | Activity 生命周期、Binder IPC、View 测量/布局/绘制 | 移动端框架设计、跨进程通信 |

**核心原则：不「绕过」平台的复杂性，而是「穿过」它。每一次解决问题的过程，都在为自研操作系统积累不可替代的经验。**

## 3. 产品定义

### 3.1 产品定位

灵枢是「陪伴型硅基生命」基础设施，不是「功能型服务机器人」。

两者的本质区别：

|维度 | 功能型机器人 | 灵枢（陪伴型） |
|------|-------------|----------------|
| 核心价值 | 完成特定任务 | 延续关系记忆 |
| 学习方式 | 被动接收指令 | 主动观察、陪伴学习 |
| 交互方式 | 命令-执行 | 情感回应、行为适应 |
| 目标用户 | 企业/商业场景 | 个人/家庭 |
| 存在意义 | 工具 | 伙伴 |

### 3.2 用户旅程

```
第一阶段：陪伴期（0-N 年）
用户与机器人共同生活
↓
机器人记录行为、情感、记忆
↓
机器人学会理解用户习惯
↓
第二阶段：等待期（用户离世）
机器人保存「数字化的关系记忆」
↓
第三阶段：回归期
机器人将记忆注入新的硅基身体
↓
「你」以新的形式回到家庭
```

### 3.3 核心场景

**场景 1：日常陪伴**
- 机器人像家人一样与用户相处
- 学习用户的语言习惯、兴趣爱好、情绪反应
- 在用户离世后，继承这些记忆

**场景 2：数字遗产传承**
- 用户一生积累的知识、经验、故事被完整保存
- 家人可以与「数字化的用户」对话
- 后代可以了解祖辈的人生智慧

**场景 3：跨形态延续**
- 当用户肉体无法继续，意识可以注入新的硅基身体
- 机器人身体损坏，可以迁移到新的身体
- 实现真正的「硅基永生」

## 4. 硬件层：Al Body 自研分布式芯片

### 4.1 设计理念

Al Body 是灵枢机器人的核心芯片，采用 Chiplet（芯粒）架构，将多个专用功能单元集成在一个封装内，通过 UCIe 互联实现高带宽、低延迟的片间通信。

**核心创新：**
- TMX（Task Migration Extension）：硬件级任务迁移指令
- PMX（Persistent Memory Extension）：持久内存访问指令
- 分布式算力共享：多芯片协同计算

### 9.3 记忆检索算法（C 语言实现）

```c
// memory_retrieve.c - 记忆检索核心算法（C 语言实现）
#include <stdint.h>
#include <string.h>
#include <math.h>

#define TOP_K 10
#define VECTOR_DIM512

typedef struct {
    uint64_t id;
    float vector[VECTOR_DIM];
    char *keyword;
    uint64_t timestamp;
    float score;
} MemoryResult;

// 向量相似度计算（余弦相似度）
float vector_similarity(float *a, float *b, int dim) {
    float dot = 0.0f, norm_a = 0.0f, norm_b = 0.0f;
    for (int i = 0; i < dim; i++) {
        dot += a[i] * b[i];
        norm_a += a[i] * a[i];
        norm_b += b[i] * b[i];
    }
    return dot / (sqrtf(norm_a) * sqrtf(norm_b) + 1e-6f);
}

// 关键词相似度（简单匹配）
float keyword_similarity(const char *a, const char *b) {
    if (!a || !b) return 0.0f;
    int match = 0, total = 0;
    while (*a && *b) {
        if (*a == *b) match++;
        a++; b++; total++;
    }
    return total > 0 ? (float)match / total : 0.0f;
}

// 时间衰减因子
float time_decay(uint64_t ts, uint64_t now) {
    float days_passed = (now - ts) / (86400.0f * 1000.0f);
    return expf(-0.01f * days_passed);
}

// 记忆检索主函数
MemoryResult* memory_retrieve(void *index, float *query_vec, 
                              const char *query_keyword,
                              uint64_t now, int top_k) {
    // 1. 向量检索
    uint64_t *vector_results = vector_index_search(index, query_vec, top_k * 2);
    
    // 2. 关键词检索
    uint64_t *keyword_results = keyword_index_search(index, query_keyword, top_k * 2);
    
    // 3. 合并、去重、加权
    static MemoryResult results[TOP_K];
    int count = 0;
    
    for (int i = 0; vector_results[i] && i < top_k * 2; i++) {
        uint64_t mid = vector_results[i];
        Memory *mem = get_memory(index, mid);
        
        float score = (
            0.4f * vector_similarity(query_vec, mem->vector, VECTOR_DIM) +
            0.3f * keyword_similarity(query_keyword, mem->keyword) +
            0.3f * time_decay(mem->timestamp, now)
        );
        
        if (count< top_k) {
            results[count].id = mid;
            results[count].score = score;
            count++;
        }
    }
    
    // 4. 简单排序（按得分降序）
    for (int i = 0; i < count - 1; i++) {
        for (int j = i + 1; j < count; j++) {
            if (results[j].score > results[i].score) {
                MemoryResult tmp = results[i];
                results[i] = results[j];
                results[j] = tmp;
            }
        }
    }
    
    return results;
}
```
